# Project Summary
Reading Companion is an AI research assistant for students and researchers who want to understand arXiv papers and trace answers back to sources. Users enter a research goal and optionally a paper ID or link. The agent plans its work, searches and reads papers, records sourced notes, answers with citations, and checks whether its claims are verified.

Completed sessions can be saved to the database, browsed in a public recent-questions gallery, and shared through a session link.

# Project Module Description
- **Research agent:** Runs in the browser, calls the LLM gateway and paper-tools service, and supports paper search, abstract lookup, sliced full-text reading, and sourced notes. It displays plans, tool calls, notes, answers, and self-checks in a live timeline, with a maximum of 12 turns.
- **Evidence and citations:** Notes include a paper ID and a quote of up to 25 words. The interface checks quote support and distinguishes full-text evidence, abstract-only evidence, and quotes that could not be found. Answers use numbered arXiv citations; unverifiable claims are identified.
- **Session management:** Saves completed goals, answers, notes, and token counts to the `reading_sessions` database table. Provides a recent-questions gallery and shareable session pages.
- **Internationalized interface:** English and Chinese UI toggle, with answers in the selected language. Includes light and dark themes and responsive mobile layouts.
- **Authentication and backend services:** FastAPI modules provide authentication, user, settings, storage, AI hub, health, and session APIs. The research agent calls the supplied LLM and paper services directly; secrets are not stored in the frontend.

# Technology Stack
- **Frontend:** React, TypeScript, Vite, Tailwind CSS, and reusable UI components.
- **Backend:** Python, FastAPI, SQLAlchemy, and Alembic.
- **Research services:** LLM gateway and arXiv paper-tools service, called directly by the browser.
- **Data:** Atoms Cloud database, using the `reading_sessions` table.
- **Quality and rendering:** ESLint, Playwright configuration, Vite plugins, and blog prerendering.

# Usage
- Install frontend dependencies from `app/frontend` with `npm install`.
- Start the frontend development server with `npm run dev`; create a production build with `npm run build`.
- Install backend dependencies in a Python environment with `pip install -r requirements.txt` from `app/backend`.
- Use `app/start_app_v2.sh` to start the application when its required environment and service configuration are available.
- Configure database and service settings for the deployment environment. Keep secrets out of frontend code.
- Apply database migrations using the project’s Alembic configuration when setting up or updating the database.
